# Localisation model: English and Spanish on miamicontactimprov.com

Read when: adding a locale, adding a translated page, changing a URL, touching
`build/locales.py`, `build/shell.py`, `build/schema.py`, `build/content_es.py`, the
language switcher, or the `i18n` / `listing-fidelity` / `disambiguation` / `a11y`
checks in `tools/gate.py`.

The site is English at the root and Spanish under `/es/`. Both locales are generated
from the same Python source, so every page carries the switcher, its own canonical and
its own side of the reciprocal hreflang pair by construction rather than by hand.

## The locale table is the single source of every URL

`build/locales.py` owns routes. Nothing else may invent one.

```python
ROUTES = {
    "jams":        {"en": "/jams",           "es": "/es/jams"},
    "miami-jams":  {"en": "/miami-jams",     "es": "/es/jams-miami-dade-broward"},
    "history":     {"en": "/history"},         # English only: no Spanish key
    ...
}
```

* A slug with two routes **is** a translation pair. That pairing generates the hreflang
  tags, the switcher options, the sitemap entries and the `_redirects` rules. There is
  no second list to keep in sync.
* `filename_for(route)` derives the output path (`/` → `index.html`, `/es/` →
  `es/index.html`, `/es/jams` → `es/jams.html`), so a new locale creates a directory
  tree without a new mapping.
* `build/build.py` pairs `(slug, locale)` with a builder, a priority and a changefreq.
  `check_tables_agree()` runs at the top of every build and stops it if the two tables
  disagree — a row in one and not the other is either a page with no URL or a URL with
  no page.

## Why a prefix (`/es/`), not a suffix or a query parameter

* **The English URLs do not move.** Root-stays-English keeps every existing canonical,
  sitemap entry, redirect rule and inbound link byte-identical. A suffix or a
  `/en/...` prefix would rewrite all fifteen English URLs and buy nothing but redirect
  debt on a property whose whole point is that its addresses are stable and quotable.
* **A locale is a directory, and a directory is one rule.** `/es/` groups the Spanish
  tree under one prefix, which is one `_redirects` line for the `/es` ↔ `/es/` pair,
  one CI assertion (`test -s site/es/index.html`), and one glob for anything that ever
  needs to treat a locale as a unit.
* **A prefix is legible in a search result.** `miamicontactimprov.com/es/jams` tells a
  Spanish reader what they are about to get before they click. A query parameter
  (`?lang=es`) is not indexable separately and a cookie-based language switch is
  invisible to a crawler entirely.
* **Cloudflare Pages clean URLs work at depth.** `/es/jams.html` is reachable as well as
  `/es/jams`, so the same `.html` → clean-URL 301 is generated per page (see
  `redirects_file()`), exactly as it is for the English tree.

## hreflang

Every page emits:

```html
<link rel="canonical" href="https://miamicontactimprov.com/es/jams">
<link rel="alternate" hreflang="en" href="https://miamicontactimprov.com/jams">
<link rel="alternate" hreflang="es" href="https://miamicontactimprov.com/es/jams">
<link rel="alternate" hreflang="x-default" href="https://miamicontactimprov.com/jams">
```

* `x-default` is always the **English** URL — the locale a reader gets if their language
  is neither. English is the default locale in `locales.DEFAULT`.
* The set is **reciprocal and complete or it is not emitted**: a locale appears only if
  this page exists in it. A page that exists in one language carries `hreflang` for that
  language plus `x-default`, and nothing else. No tag ever points at a URL the build did
  not write.
* These are emitted by `shell.head()`, so a new page cannot be built without them.

## The language switcher

Top of every page, inside the header row, always visible — including on mobile, where the
primary nav collapses behind the hamburger. A switcher hidden behind a menu button is a
switcher most readers never find.

```html
<nav class="lang-switch" aria-label="Language / Idioma">
  <a class="lang-item" href="/jams" lang="en" hreflang="en">English</a>
  <span class="lang-item is-current" lang="es" aria-current="true">Español</span>
</nav>
```

Rules, all of them enforced by the gate:

1. **A locale is offered only if it is a page that exists.** Nine pages are English-only
   (`/miami`, `/classes`, `/history`, `/glossary`, `/videos`, `/directory`,
   `/keep-practising`, `/about`). On those, the Spanish option links to `/es/` — the
   Spanish home — and not to a Spanish version of the page, because there isn't one.
2. **A fallback link carries no `hreflang`.** `hreflang` asserts "the same page, in
   another language". A home page is not that, so declaring it would be a false
   equivalence and search engines treat it as one. The fallback link carries
   `lang="es"` and a `title` saying the page is not translated yet, in the language of
   the reader who will act on it.
3. **Every switcher link resolves to a file in the build.** This is the check that
   matters: a switcher that 404s is worse than no switcher.
4. **Footer and nav links do the same thing in reverse.** A Spanish nav that has no
   Spanish destination (Miami, Clases, Directorio, Vídeos, Acerca de) links to the
   English page and marks the anchor `lang="en" hreflang="en"`, so assistive technology
   and a browser's translator know the destination is English.
5. Labels are written in their own language (`English`, `Español`), each with `lang=`.
   The `aria-label` is `"Language / Idioma"` so it is legible either way.

Switcher CSS lives at the bottom of `site/assets/site.css` under a comment explaining
that **`site/assets/site.css` is a hand-maintained source file, not generated output** —
nothing in `build/` writes it (`build/make_assets.py` writes only the rasters), which is
why editing it directly is correct here and why `site/` being generated output is not a
contradiction. Bump the `?v=` query in `shell.STYLESHEET` whenever it changes, or
returning visitors keep the 7-day cached copy from the `/assets/*` rule in `_headers`.

## Spanish terminology, chosen once and used everywhere

| English | Spanish | Why |
| --- | --- | --- |
| Contact Improvisation (CI) | **Improvisación de Contacto (IC)** | `improvisación de contacto` is the term used by Spanish-speaking CI communities and is a real translation. `contact improvisation` is named as the English original on first use on every page, because that is the string people actually search for. |
| contact improv | **contact improv** (left untranslated) | A search term, not prose. The same reason `improv` is left as-is in the trap section: translating it would hide the string a reader typed. |
| jam | **jam** | Every Spanish-speaking CI community uses the loanword. `encuentro` or `sesión abierta` would read as a different event to anyone who knows the form. `sesión` is used as the generic noun, `jam` as the name of the thing. |
| the small dance | **small dance** (technique term), `la pequeña danza` in gloss | It is a proper name for a specific practice, like the Underscore. Renaming it would break the link between the page and the literature. |
| Underscore | **Underscore** | Same: a proper name. |
| spotting / spotter | **spotting / spotter** | Used untranslated in Spanish-language CI teaching. `ojeador` (the sports sense) is wrong here. |
| consent | **consentimiento** | Standard, and the phrase `el consentimiento es continuo` mirrors the English "consent is continuous". |
| modality | **modalidad** | Used on every listing entry, exactly as the English does. |
| jam list | **lista de jams** | Names the artefact; `listado` is used for a third party's listing (e.g. "el listado de Eventbrite"). |
| checked (a source) | **comprobado el \<fecha\>** | The date stays an ISO date, untouched. See below. |
| the brand | **Miami Contact Improv** | Not translated. It is the entity name in JSON-LD, the mailbox and the domain. |

Titles keep the site's bracket convention (`[Guía]`, `[Paso a paso]`, `[2026]`) because
Max's decision for this property is that bracket keywords live in the titles, and the
Spanish titles are titles. Every bracket is true of its page, as on the English side.

## Honesty rules under translation

Translation is the easiest place to overstate, so these are rules, not style:

1. **A Spanish page may not claim anything the English page does not.** Where the English
   hedges ("we could not verify", "not a CI jam", "this site does not list it as
   running"), the Spanish hedges identically. Nothing was strengthened in translation.
2. **Listing data is quoted, not translated.** Session names, modalities, venues,
   schedules and prices are reproduced verbatim from `build/listings.py` in the organiser's
   own language, with the ISO date the source was checked unchanged. Only the field
   *labels* are Spanish, and every Spanish listing page says so in prose
   (`content_es.LIST_VALUE_NOTE`). Translating a quoted schedule would be inventing a
   quote, and a translated modality is a claim about the practice that the organiser did
   not make.
3. **The disambiguation sentence is per-locale and comes from one place.**
   `build/schema.py` owns `DISAMBIGUATION_BY_LANG`; the Spanish phrase is
   `no es un estudio, organizador ni organismo de membresía` and asserts exactly what
   `not a studio, organiser or membership body` asserts. `tools/gate.py` reads the map
   and asserts the phrase matching the language each page declares on `<html>`. The
   English string keeps its own name (`DISAMBIGUATION`) because `llms.txt`, which is the
   English discovery file, quotes it.
4. **Dates stay dates.** Every listing keeps its `Comprobado el 2026-09-14`. A Spanish
   reader gets the same check date as an English one, and the gate measures it.
5. **No city or county is added.** The Spanish pages own Miami-Dade and Broward and
   nothing else, exactly like the English ones. No city × topic matrix exists in either
   language, by Max's decision.
6. **The Miami/Queensland-Australia traps stay excluded in both languages.** The Spanish
   jam list repeats the comedy-`improv` exclusion and the undated-listing exclusion.
7. **The Spanish FAQ states its own scope.** It carries the practice, beginner, jam,
   safety, history, Miami and practical-purchase buckets; the two Q&A that point at
   English-only surfaces (the teachers register, a page with no Spanish version) link to
   the English page with `lang="en"` rather than to a page that does not exist.

| `sitemap.urls` | 22 | 15 + 7 |
| `redirects.rules` | 28 | 20 + 7 per-page rules + 1 `/es` ↔ `/es/` |
| `links.internal` | 674 | was 450 |

### Changes the i18n work forced on existing checks

* **`check_a11y` no longer requires the literal string `lang="en"`.** It parses
  `<html lang="…">` and requires the value to be one of the locales
  `build/locales.py` declares. The old substring test failed a correctly marked Spanish
  page and could pass a page with no `lang` attribute that merely contained the string
  somewhere. Negative-tested both ways.
* **`check_disambiguation` is per-locale** (above). Negative-tested by deleting the
  Spanish phrase from a Spanish `Organization` node.
* **The placeholder regex no longer matches the word "todo".** `\bTODO\b` was compiled
  case-insensitively together with the other markers, so ordinary Spanish prose ("todo lo
  que…") was reported as placeholder text — a gate that forbids a language. The shouted
  markers (`TODO`, `TBD`, `FIXME`, `XXX`) are now case-sensitive and the phrase-like ones
  are not. Negative-tested by injecting a real `<h1>TODO`.
* **`main()` globs recursively (`rglob`).** A non-recursive `glob("*.html")` would have
  measured only the English tree while reporting a full green run. Page keys are now
  site-relative (`es/jams.html`) so a finding names the file it came from.
* **`.github/workflows/publish.yml` no longer uses `find site -maxdepth 1`.** The
  "assert the gate measured the whole surface" step counted 16 pages while the gate
  measured 23, so it had stopped covering the Spanish tree; it now recurses with a floor
  of 20 and also asserts `site/es/index.html` exists. The canonical-host step used
  `site/*.html` and was equally blind to `/es/`.

### New checks, and how each was proven to fire

| check | negative test | result |
| --- | --- | --- |
| switcher link resolves | point a switcher at `/es/does-not-exist` | exit 1, `language switcher link does not resolve` |
| every alternates set is self-referencing with one `x-default` | delete `<html lang>` | exit 1, `alternate set does not reference itself` |
| an hreflang target must be a URL the build wrote | repoint the Spanish alternate at `/es/ghost/` | exit 1, `points at a URL the build did not write` |
| reciprocity | delete the `en` alternate from `/es/jams` | exit 1, `is not reciprocated` |
| `a11y` accepts declared locales only | `lang="es"` → `lang="es-MX"` | exit 1, `is not one of the declared locales` |
| per-locale disambiguation | delete the Spanish phrase | exit 1, `does not state 'no es un estudio…'` |
| every listing page carries every modality | strip one modality from `/es/jams` | exit 1, `is missing its modality` |
| every listing page carries every checked date | strip `2026-09-14` from `/es/jams` | exit 1, `is missing its checked date` |
| a real placeholder is still caught | inject `<h1>TODO` | exit 1, `placeholder text in markup: ['TODO']` |
| measuring nothing is a failure | strip all hreflang / all switcher navs / empty `LISTING_ROUTES` | exit **2** |

## Adding a third locale

1. Add a row to `build/locales.py`: the locale code in `LOCALES`, its `HTML_LANG`,
   `SCHEMA_LANG`, `OG_LOCALE` and `LOCALE_LABEL` entries, and a route for every slug in
   `ROUTES` that the locale is going to have. **Add only the routes you have pages for** —
   a locale listed for a slug the build does not write is what the i18n check exists to
   catch, and it will fail the build.
2. Add the locale's disambiguation phrase and scope sentence to
   `SITE_SENTENCE_BY_LANG` / `DISAMBIGUATION_BY_LANG` / `_DISAMBIGUATING_TAIL_BY_LANG` in
   `build/schema.py`. The gate refuses a page whose language the map does not cover, so
   this is not optional and cannot be deferred.
3. Create `build/content_<locale>.py` mirroring `build/content_es.py`, and add one
   `PAGES` row per page in `build/build.py`. `check_tables_agree()` fails the build until
   `locales.ORDER` and `PAGES` agree.
4. Extend `build/shell.py`: `NAV` and `FOOTER_COLS` labels and `SKIP_LABELS`. The
   switcher labels come from `locales.LOCALE_LABEL` and the footer colophon is the last
   locale-specific string in that file.
5. Add the new locale's routes to `LISTING_ROUTES` in `tools/gate.py` if it has listing
   pages, and give it its own listing field labels.
6. Bump `shell.STYLESHEET` if the switcher now needs a wider row.

No step is optional and none of them is a second place to record a URL: the URL is only
ever in `locales.ROUTES`.

## Known limits, stated rather than hidden

* **Nine English pages have no Spanish version and the switcher says so** by pointing at
  the Spanish home with a title explaining it. A Spanish reader who lands on `/history`
  from a search result gets an English page and one obvious way to the Spanish tree.
  Translating those nine is the next slice if it is wanted; each one is a `PAGES` row and
  a route.
* **`/es/404.html` does not exist.** One 404 document serves both locales. A missing URL
  is missing in both languages, and a second document would be a second thing to keep in
  sync for no reader benefit.
* **The Spanish pages carry no `Event` schema.** `listings.events_schema()` publishes
  Event nodes with English descriptions; emitting them on a Spanish page would publish
  English prose under a Spanish page. The Spanish jam list therefore carries the
  `ItemList` of sessions (name, organiser URL, modality) instead. The Events are still
  published once, from the English `/jams` and `/miami-jams` pages.
* **`og:image` is one English raster for both locales.** `og:image:alt` is English on the
  Spanish pages. A Spanish social card is a design task, not a translation task, and it
  has not been done.
* **`llms.txt` and `llms-full.txt` are English.** They list the Spanish URLs and say what
  `/es/` is, but there is no Spanish discovery file. If answer engines start asking for
  one, the honest version is a generated `es/llms.txt`, not a hand-written copy.
* **No Spanish page was machine-translated and none should be.** Every Spanish page in
  `build/content_es.py` was written as Spanish, checked against its English counterpart
  claim by claim, and the gate now measures the parts of it that carry a claim (modality,
  check date, disambiguation).
